# TSPhysicalAI — 시계열 기반 에너지 운영 가상실습

건물 부하와 태양광 발전 시계열을 입력하여 **예측 → 운영 판단 → 가상 ESS 동작 → 상태 관측 → 계획 수정**을 학습하는 웹 프로그램입니다. ESP32, 배선, GPU, 외부 API 없이 PC에서 실행합니다.

화면의 ESS는 수식으로 상태를 갱신하는 시뮬레이터입니다. 실제 배터리나 건물을 제어하지 않으며, 기본 자료는 **합성 시연 데이터**입니다. 저장소의 `power_loads/`와 `pv_new/`는 별도 원본 자료이며, 프로그램이 자동으로 읽거나 학습하지 않습니다. 실제 자료를 사용하려면 아래 형식으로 검증·변환한 CSV를 불러옵니다.

## 프로그램 다운로드

[프로그램 전용 ZIP 다운로드](https://github.com/kwonmail900/TSPhysicalAI/raw/refs/heads/main/downloads/TSPhysicalAI_Education_v1.zip)

전용 ZIP에는 소스·실행 스크립트·교육 문서·테스트가 들어 있으며 원본 자료 폴더는 제외되어 있습니다. 압축을 풀고 `TSPhysicalAI` 폴더의 `start_windows.bat`를 실행하거나 아래 명령을 사용합니다. 저장소 전체가 필요하면 GitHub의 **Code → Download ZIP**을 선택합니다.

## 실행

Python 3.10 이상이 필요합니다. 기본 실행에는 별도 패키지 설치나 인터넷 연결이 필요하지 않습니다.

```bash
cd TSPhysicalAI
python server.py --host 127.0.0.1 --port 8765
```

Linux/macOS에서 `python`이 없다면 `python3`를 사용합니다. Windows에서는 Python을 설치한 뒤 `start_windows.bat`를 실행할 수 있습니다. 실행한 PC의 브라우저에서 `http://127.0.0.1:8765`를 엽니다. 서버를 종료하려면 터미널에서 `Ctrl+C`를 누릅니다.

이 주소는 개인 PC에서 사용하는 로컬 주소이며, 외부에 공개된 사이트가 아닙니다. 학생별로 프로그램을 실행하여 사용하는 구성을 기본으로 합니다.

## 첫 실습

1. 기본 합성 자료와 시간별 해상도로 비교 실험을 실행합니다.
2. 부하·발전 예측과 실제 자료의 차이를 확인합니다.
3. ESS 없는 기준, 현재값 대응, 하루 전 계획, 피드백 재계획의 결과를 비교합니다.
4. 한 정책의 시간 흐름을 재생하며 관측값, 제안 명령, 적용 명령, SOC를 확인합니다.
5. 태양광 감소나 부하 급증 시나리오로 바꾸고 같은 설정에서 다시 실행합니다.
6. 결과와 개인 성찰 기록을 내려받아 차이가 생긴 이유를 설명합니다.

정책 이름이나 예측 모델의 복잡도만으로 성능 순위를 정하지 않습니다. 발전 패턴, 저장 용량, 효율, 최종 잔량에 따라 구매전력과 자가소비 결과가 달라집니다.

브라우저 없이 같은 실험 결과를 저장하려면 다음과 같이 실행합니다. 출력 경로에 비교표, 정책별 CSV와 JSON을 생성합니다.

```bash
python experiment.py --resolution hourly --scenario pv_drop --output outputs/pv-drop
```

화면과 명령행에서 내려받는 전체 실험 JSON에는 예열 7일을 포함한 `input_records`와 입력 확인용 `input_sha256`이 들어갑니다. 입력, 설정, 프로그램 버전을 함께 보관하여 재현에 사용합니다. 시드는 합성 자료 생성에만 사용하며, 업로드한 자료의 실험에는 무작위 변동을 추가하지 않습니다.

## 구성 요소

| 구성 | 현재 구현 범위 |
|---|---|
| 시계열 예측 | 전주 같은 시점의 값, 이용 가능한 과거 1~4주 같은 요일·시각 평균 |
| 운영 에이전트 | 목표와 제약을 확인하는 결정형 규칙 정책 |
| 가상 환경 | 부하·태양광·ESS의 구간별 에너지 수지와 저장 상태 |
| 피드백 | 직전까지 관측한 상태를 다음 운영 판단에 반영 |
| 오류 시나리오 | 부하 급증, 발전 감소, SOC 관측값 정체 |
| 교육 도구 | 정책 비교, 단계별 재생, 결과 내보내기, 학습 과제 |

**사전학습 TSFM, LLM, 강화학습, MPC는 현재 구현하지 않았습니다.** 기준 예측과 규칙 정책으로 폐루프 개념을 먼저 학습하도록 구성했습니다. 해당 모델을 실제로 추가하고 검증하기 전에는 결과를 TSFM·LLM 결과로 표기하지 마십시오.

## CSV 자료 준비

CSV는 UTF-8 형식으로 저장합니다. 한 번에 건물 한 개 또는 합산 범위가 명확한 계량 경계의 부하와 태양광을 입력합니다.

```csv
timestamp,load_kwh,pv_kwh
2023-01-01T00:00:00,12.4,0.0
2023-01-01T01:00:00,11.8,0.0
2023-01-01T02:00:00,11.6,0.0
```

위 세 행은 **형식 예시**입니다. 실험용 입력은 충분한 연속 기간을 포함해야 합니다. 날짜를 임의로 늘리거나 결측을 실제값처럼 채우지 마십시오.

| 열 | 의미 |
|---|---|
| `timestamp` | 구간 시작 시각. 한 현장의 동일한 현지 시간 기준 |
| `load_kwh` | 해당 구간의 건물 소비 에너지, kWh |
| `pv_kwh` | 해당 구간의 태양광 발전 에너지, kWh |

**입력값은 구간 에너지이며 순간 전력 kW가 아닙니다.** 누적 계량값도 그대로 입력하지 않습니다. 전력 자료는 해당 구간에 대해 적분하고, 누적 계량 자료는 리셋·결측·구간 길이를 검증하여 차분해야 합니다.

- 시간별 모드: 자정에 시작하는 연속된 완전한 날짜, 한 시간 간격의 정시 자료를 사용합니다. 최소 15일, 즉 360행이 필요합니다.
- 일별 모드: 하루 간격, 자정 또는 날짜 기준, 하루 전체의 kWh를 사용합니다. 최소 15행이 필요합니다.
- 업로드는 최대 20,000행까지 허용하며 추가 열은 사용하지 않습니다. UTF-8 BOM도 허용합니다.
- HTTP 요청 전체는 최대 4MB입니다. 대형 CSV는 기간을 선택하여 나누거나 명령행 입력 기능을 사용합니다.
- 같은 시각의 중복, 누락, 음수, 무한대, 숫자가 아닌 값을 먼저 처리합니다. 서로 다른 시간대의 자료는 업로드 전에 시간 기준을 맞춥니다.
- 날짜·계량 경계가 같은 부하와 발전을 결합합니다. 부하가 이미 태양광을 차감한 순수전량인지 확인해야 발전을 이중 차감하지 않습니다.
- 상위 배전계와 하위 건물계를 중복 합산하지 않습니다.
- 태양광 자료가 없으면 `pv_kwh=0`으로 부하 중심 실습을 할 수 있습니다. 다른 기간·현장의 태양광을 붙인 경우 실제 동시 관측이 아닌 시나리오임을 기록합니다.

초기 7일은 전주 기준 예측을 위한 이력으로 사용하며, 정책 비교는 이후의 공통 구간에서 수행합니다. 같은 요일 평균은 그 시점에 이용 가능한 과거 1~4주의 값으로 계산합니다. 화면에 표시되는 평가 구간과 관측 수를 확인하십시오.

## 시간별과 일별의 차이

| 항목 | 시간별 모드 | 일별 모드 |
|---|---|---|
| 한 단계 | 1시간 | 24시간 |
| 실습 범위 | 시간별 에너지 이동과 구매전력 비교 | 일일 에너지 수지와 저장량 배분 |
| 전력 지표 | 구간 평균 구매전력의 최대값 | 일평균 구매전력의 최대값 |
| 해석 한계 | 구간 내 순간 피크는 관측하지 않음 | 시간대별 피크·충방전 순서를 알 수 없음 |

일별 실험은 하루를 하나의 에너지 구간으로 취급하는 단순 모형입니다. 실제 하루 안에서 저장·방전이 가능한 시점이나 전력요금의 시간대별 효과를 입증하지 않습니다. 일별 kWh로 실제 시간별 부하를 복원했다고 해석하면 안 됩니다.

일별 모드에서는 실제 발전과 부하의 구간 내 겹침을 알 수 없어 PV 자가소비율을 계산하지 않습니다. ESS 없는 기준의 SOC와 저장 에너지도 해당 없음으로 표시합니다.

## ESS와 결과 해석

ESS에는 저장 용량, 충·방전 출력 한계, SOC 범위, 편도 효율을 적용합니다. 충전 에너지와 방전 에너지는 계통 측 기준으로 기록하며, 저장량은 효율을 반영해 갱신합니다. 출력 요청이 허용 범위를 넘으면 환경이 적용 가능한 값으로 제한하므로, **제안 명령과 적용 명령은 다를 수 있습니다.**

서로 다른 정책에는 같은 입력 자료·초기 SOC·용량·효율·시나리오를 적용합니다. 부하 급증·발전 감소·SOC 관측값 정체 시나리오는 평가 중간의 날짜에 시작하여 이틀 동안 적용됩니다. `센서값 정체`는 물리적 저장 상태가 멈춘다는 의미가 아니라, 운영 판단이 사용하는 SOC 관측이 갱신되지 않는 상황입니다.

현재값 대응 정책은 해당 구간의 집계된 부하·발전을 즉시 관측할 수 있다고 가정합니다. 예측 정책은 이전 구간까지 확인된 정보로 판단합니다. 이 정보 차이는 연속시간 현장 제어를 그대로 재현하는 것이 아니라 구간 모형의 교육용 가정입니다. 하루 전 계획 정책도 매일 자정의 관측 SOC로 하루 계획을 다시 세우므로, **하루 중 계획을 유지하는 비교군**으로 해석합니다. 피드백 재계획은 구간별로 상태와 확인된 예측 잔차를 반영합니다.

관측값 정체 시나리오는 **SOC 관측 채널만** 정체시킵니다. 독립된 부하·태양광 계측 채널은 유효한 값을 계속 제공하며, 순부하 관측과 확인된 예측 잔차 갱신도 유지됩니다. 실제 환경의 SOC·출력 한계 적용은 계속 유지됩니다. 따라서 이 시나리오는 저장량 관측 이상으로 인한 판단 성능을 확인하며, 물리적 보호 기능을 제거하는 실험이 아닙니다.

구매전력만 비교하면 초기 배터리에 저장된 에너지를 더 많이 소모한 정책이 유리해질 수 있습니다. **초기·최종 SOC와 배터리 손실을 함께 제시**하고, 초기·최종 잔량이 다르면 이를 보정하지 않은 구매전력 감소를 순수한 절감 효과로 주장하지 마십시오. PV 자가소비율은 발전량 중 즉시 부하 또는 충전에 사용한 비율이며, 이후 저장 손실까지 반영한 최종 유효 공급 비율과 다릅니다. 프로그램의 물리적 에너지 수지 검증과 정책 성능 비교는 서로 다른 평가입니다.

## 검증

```bash
python -m unittest discover -s tests -v
```

물리식의 에너지 보존, 출력·SOC 한계, 입력 검증, 예측·판단의 시간 순서, HTTP 동작을 자동 테스트로 확인합니다. 자동 테스트 통과가 실제 설비 성능이나 교육 효과 검증을 대신하지는 않습니다.

교육 적용은 [6주 수업안](docs/LESSON_PLAN.md), 후속 논문 설계는 [연구 가이드](docs/RESEARCH_GUIDE.md)를 참고하십시오.
